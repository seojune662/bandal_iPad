# iPad UI redesign coverage

The shipped interface is `App/BandalApp.swift → DesktopShell → DesktopRuntime`
and its adapted React/Dockview renderer. The legacy SwiftUI workspaces and
`WebEditor` are not the active shell and were not redesigned in this change.
The upstream snapshot, native IPC contracts, persistence formats, PDF geometry,
ink history and document content are outside the presentation change.

## Implementation ownership

| Area | Files and responsibility |
| --- | --- |
| Shared visual system | `DesktopRuntime/renderer/ipad/ui/base.css`: light/dark semantic colors, touch targets, button states, chrome typography, contrast and compact-density behavior. Original root font scale and document text tokens remain intact. |
| Integration | `DesktopRuntime/renderer/ipad/ui/index.mjs` and `styles.css`: strict source-adapter integration and ordered imports; the immutable upstream source is not edited. |
| Shell/navigation | `DesktopRuntime/renderer/ipad/layout/`: sidebar, tabs, panel dimensions, settings presentation and existing native-surface coordination. |
| Settings/AI | `ui/settings.css`, `ui/chat.css`, `ui/settingsChatPlugin.mjs`, `ui/IpadComposerPopover.tsx`: settings rows and navigation, chat reading/composer layout, touch actions and anchored composer popovers. |
| Feature surfaces | `ui/surfaces.css`: drawing palette chrome, document headers, learning, recording, dialogs/menus/toasts, boards/widgets, browser auxiliary controls, school/account/sync/plugin/market/link/help/onboarding/PiP chrome. No new event handlers or data writes. |

## What was exercised

“Actual component” below means that the fixture imports the product React
component with local test callbacks/IPC. It does not mean a real account,
microphone, native PDF view, payment, sync service or external website was used.
“Layout specimen” means representative DOM using the real production CSS;
it verifies layout but not the full feature's behavior.

## Surfaces test result and states

`node renderer/ipad/ui/test-surfaces.mjs` passes in WebKit for both light and
dark themes at 1194×900, 834×900, 507×700, 375×700 and 375×400, plus 507×700
with 125% font scale: 12 configurations total. Assertions measure rendered
bounding boxes, not just authored CSS. They include long Korean strings,
form-descendant containment, selection, dismissal, viewport fit,
notification wrapping, original callback counts and unchanged document ink.

The tests exposed and fixed WebKit's native select height clamp and narrow
column-form intrinsic-width overflow. Selects retain native selection behavior
with custom chrome; learning form controls are bounded by their own form.

The new surfaces fixture does not simulate actual keyboard occlusion. The
settings/chat and layout fixtures exercise simulated `visualViewport` changes;
neither substitutes for testing a docked/floating keyboard on iPadOS.

Browser layout specimens are also captured at 375/light, 507/dark and

under `docs/fixtures/ipad-ui-redesign/browser-*.png`.

Run `node renderer/ipad/ui/test-surfaces.mjs --capture-before` to produce the
matching `-before.png` files. Baseline mode omits **only** `ui/styles.css` and
retains the actual upstream reset and existing iPad layout/touch adapters. It is
a controlled comparison of the shared UI layer, not a historical screenshot of
the entire application before every shell change. The baseline capture mode
does not claim that the redesigned-control assertions passed against old CSS.

Representative images were visually reviewed for rhythm, dark-theme contrast,
multiline labels and narrow control layout. Screenshot coverage is limited to
these representative states; this document does not claim all screens or all
error/empty/loading states were visually tested.

## Native regression boundary

Use the existing input/native-surface/PDF/browser/keyboard and XCTest suites to
verify native interaction after rebuilding the canonical bundle. Relevant
invariants are: HTML overlay masks match measured boxes; settings/dialogs block
native input; palette drag release follows the final geometry acknowledgement;
Pencil/finger behavior, document coordinates, save/reopen and export remain
unchanged. This coverage record distinguishes those required native checks from
the browser-only visual results above; it does not assert a device run occurred.
