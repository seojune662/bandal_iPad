# iPad 브라우저·PDF 내보내기·미디어 개선 — 2026-10-21

이 문서는 브라우저 화면, PDF 팔레트, 자료 사이드바의 필기 포함 내보내기, 이미지 편집, 과목 전환 후 PDF 열기 개선을 기록한다. 기존 작업을 포함한 저장소 전체 변경량과 이번 검증 범위는 같지 않다. 아래 테스트 수는 이번 변경에 관련된 실행 결과다.

**현재 기록 상태:** 관련 단위·통합 테스트, 성능 재검증과 마지막 브라우저 UI 3개 흐름이 통과했다. 실제 기기에 `1.0.0 (6)`을 설치하고 일반 실행을 확인했다. 설치 전후 자료 파일 86개와 기존 PDF 필기·화이트보드 행의 모든 저장값이 동일함을 확인했다.

## 화면과 사용 동작

### 브라우저

일반 새 탭은 설정한 홈페이지를 실제 WebKit 페이지로 연다. 홈페이지가 비어 있으면 선택한 검색 엔진의 홈페이지를 사용하며 기본값은 Google이다. 비공개 새 탭은 사용자가 주소를 입력하기 전까지 로컬 빈 페이지를 유지한다. 전달받은 링크를 열 때는 별도의 홈페이지를 먼저 방문하지 않는다.

주소창은 둥근 형태로 바꾸고 뒤로·앞으로·새로고침, 프로필, 세로 더보기 메뉴를 배치했다. 좁은 분할 화면에서도 뒤로와 새로고침을 유지하고 공간에 따라 앞으로·홈·프로필 표시를 조절한다. 로딩 진행률은 도구 막대 아래에 겹쳐 표시해 웹페이지가 위아래로 밀리지 않게 했다. 기존 방문 기록·페이지 검색·확대율·다운로드·프로필 격리 기능을 유지한다.

Chrome과 익숙한 탐색 구조를 맞춘 변경이며, 렌더링 엔진은 기존 WebKit이다. Chromium 엔진이나 Chrome 확장을 추가한 것은 아니다.

### PDF 팔레트

팔레트 오른쪽의 검정·파랑·빨강 아래 `1`, `2`, `3`은 저장된 펜 스타일을 바로 선택하는 프리셋 버튼이었다. 이 세 바로가기를 도구 막대에서 제거했다. 색상·굵기·불투명도와 펜·형광펜별 설정은 계속 사용할 수 있으며 좁은 창에서는 편집 도구가 전체 가로 공간을 사용한다.

### 사진·파일과 이미지 편집

자료 사이드바 하단의 **사진**, **파일** 버튼은 보관함이 접혀 있어도 글자와 함께 표시한다. 사진은 시스템 Photos 선택기를, 파일은 iPadOS 파일 선택기를 연다. iPad에서 Finder에 대응하는 파일 접근 경로는 파일 앱과 연결된 파일 제공자다.

선택한 항목을 보관함에서 PDF 또는 Markdown으로 끌어 넣는 기존 경로를 유지했다. PDF에는 이미지를 놓을 수 있고, Markdown에는 이미지와 파일 첨부를 넣을 수 있다. 외부 파일 제공자가 임시 URL을 회수하기 전에 내용을 확보하고 대상 문서 과목의 자산으로 저장한다.

- PDF 이미지는 삽입 직후 선택 도구로 전환하고 선택 상태를 유지해 위치 이동과 모서리 크기 조절을 바로 시작할 수 있다. 이전 펜 스타일은 유지된다.
- Markdown 이미지를 누르면 크기 슬라이더, 왼쪽·가운데·오른쪽 정렬, 본문에서 위·아래 이동, 삭제를 사용할 수 있다.
- Markdown의 이미지 경로와 제목은 유지하고 인접한 HTML 주석에 배치 정보를 저장한다. 원문 모드·실행 취소·저장·재열기에 설정이 유지된다. 일반 Markdown 도구는 이미지 링크를 계속 읽을 수 있지만 Bandal 전용 배치 주석의 크기·정렬을 적용하지 않을 수 있다.
- 정렬만 바꿀 때 작은 이미지가 커지지 않도록 자연 크기를 보존한다. 세로 이미지도 종이 높이에 맞추면서 가로세로 비율을 유지한다. 한글 조합 입력을 마치며 이미지 앞쪽 글자 수가 변한 경우에는 새 원문 범위로 이미지를 다시 찾는다.

화면: [PDF 이미지 드롭](ipad-browser-media-2026-10-21/pdf-image-drop.png), [Markdown 이미지 조절](ipad-browser-media-2026-10-21/markdown-image-controls.png).

## 자료 사이드바에서도 필기를 포함한 PDF 전달

PDF 편집 화면의 공유는 원본과 저장된 필기를 합성했지만 자료 사이드바는 원본 파일 사본을 전달했다. 필기가 별도 저장소에 있으므로 이 경로에서는 필기가 빠질 수 있었다.

자료의 **공유**와 **파일로 내보내기**는 열린 문서의 보류 중 편집을 저장한 뒤 PDF 편집 화면과 같은 `nativePDF:exportBytes` 합성 경로를 사용한다. PDF 필기·추가 이미지·주석을 포함한 사본을 공유하거나 시스템 파일 내보내기 화면에 넘긴다. 저장·합성·문서 연결 검증이 실패하면 오류를 반환하며 필기 없는 원본으로 대신 내보내지 않는다.

자료 목록에서 PDF를 외부 앱으로 드래그하는 경우에도 수신 앱이 파일을 요청할 때 저장을 마치고 합성 PDF를 준비한다. 수신 앱이 필기 없는 원본을 선택할 수 없도록 원본 파일 URL 표현은 제공하지 않는다. 임시 PDF는 드래그 제공자의 수명 동안 유지한다.

주요 경로는 `NativeWorkspaceStore.performNativeChannel`, `DesktopFileServices.materialSnapshot`, `NativeLibraryPDFDragExport`다. PDF 원본과 별도 편집 저장소를 유지하는 앱의 저장 방식은 그대로다.

## PDF 열기 성능

다른 과목으로 이동했다 돌아왔을 때 이미 읽었던 필기 JSON을 다시 해석하는 비용을 줄였다. 저장소는 SQL과 문서 연결 검증을 계속 수행하고, 필기 데이터·스타일의 **저장된 UTF-8 바이트가 같은 경우에만** 해석 결과를 재사용한다. 타임스탬프나 개체 ID만 같다는 이유로 오래된 내용을 반환하지 않는다. 직접 SQL 변경, 실행 취소, 삭제 및 잘못된 JSON을 다루는 회귀 검사를 포함한다.

캐시는 최대 12,000행과 추정 비용 256 MiB로 제한하고 최근 사용 순서에 따라 비운다. 메모리 압력 알림에서는 저장소와 같은 직렬 큐에서 캐시를 해제한다. 캐시에 없는 문서나 여러 대형 문서에 의해 밀려난 필기는 다시 해석한다.

완료된 필기의 Metal 삼각형 버퍼는 실시간 입력용 중간 캐시를 거치지 않고 직접 작성한다. 기존의 점 순서·Float 변환·삼각형 바이트·경계 계산을 유지하면서 중복 배열과 경계 계산을 줄였다. 이전 렌더링과의 GPU 삼각형 바이트 일치를 별도로 검사했다.

### 시뮬레이터 측정

원자료는 [performance.json](ipad-browser-media-2026-10-21/performance.json)이다. **iPad iOS 26.3 시뮬레이터의 Debug 빌드**에서 같은 로컬 PDF 사본을 사용했다. 실제 iPad에서 잰 시간이 아니다. 재현 자료는 6페이지, 필기 7,094행, JSON 53,658,974바이트이며 비공개 파일·이름·본문은 저장소에 넣지 않았다.

| 작업 | 변경 전 | 변경 후 |
|---|---:|---:|
| 같은 시뮬레이터 사본의 문서 열기 | 5.237초 | 3.204초 |
| 페이지 추가 | 4.622초 | 2.996초 |
| 다른 빈 과목으로 전환한 뒤 다시 열기, 1회 | 비교값 없음 | 2.098초 |
| 다른 빈 과목으로 전환한 뒤 다시 열기, 2회 | 비교값 없음 | 2.151초 |

열기는 약 39%, 페이지 추가는 약 35% 짧아졌다. 첫 시뮬레이터 부팅 직후 측정치는 위 비교에서 제외했다. 과목 전환 후 두 번의 재열기에서는 새 JSON 해석이 각각 0건이었다. 문서 크기, 캐시 상태, 파일 제공자, 실제 기기 환경에 따라 걸리는 시간은 달라진다. 이 결과는 모든 문서가 즉시 열리거나 실기기에서 같은 시간이 나온다는 보장이 아니다.

이미지 편집은 원문 배치 주석·자산 경로 보존, 크기·정렬·이동·실행 취소·디스크 재읽기, 작은 이미지 정렬 시 크기 유지, 세로 이미지 비율, 한글 조합 입력 뒤 이미지 선택을 검사한다. 실제 UI 테스트에서는 사진 보관함에서 이미지 드롭 후 이미지 팝오버의 슬라이더·가운데 정렬·위로 이동을 조작하고 앱 재시작 뒤 원문이 같은지 확인한다.

자료 PDF 전달은 필기 포함 합성 경로, 편집 저장 장벽, 외부 드래그 제공자가 원본 URL을 노출하지 않는 조건을 검사한다. 시뮬레이터 UI 결과와 실제 기기 설치·자료 보존 결과는 별개로 기록한다.

## 실제 기기 업데이트와 백업

**Release `1.0.0 (6)`**을 iPad Pro 11형 3세대(iPadOS 26.5)에 설치했다. 앱과 공유 확장의 버전·서명·프로비저닝 프로필·App Group을 검사하고, 테스트 인자 없이 일반 실행한 프로세스를 확인했다. 서명 검증은 [device-signing.json](ipad-browser-media-2026-10-21/device-signing.json)에 기록한다.

| 항목 | 현재 결과 |
|---|---|
| 설치 전 Documents 백업 | **성공**, 약 1.6 GB |
| 설치 전 Preferences 백업 | **성공** |
| 설치 전 App Group ShareInbox 별도 백업 | **실패**, `ContainerLookupErrorDomain` 코드 `7`로 두 번 실패 |
| `1.0.0 (6)` 서명·설치·일반 실행 | **성공** |
| 설치 전후 Documents 비교 | **통과**, 자료 파일 86개 모두 해시 동일·누락 없음, 기존 필기 행 전체 값 동일, SQLite 4개 무결성 통과 |
| 설치 전후 Preferences 비교 | 46개 키 모두 유지, 43개 값 동일. 결제 확인 시각·PDF 읽기 위치·설정 연결 이력만 갱신 |
| 설치 후 ShareInbox 백업 | **성공** |
| 업데이트 후 App Group 접근 | **성공**, 공유 컨테이너와 `ShareInbox` 디렉터리 접근 확인. 이전 내용과의 비교는 설치 전 백업 부재로 확인할 수 없음 |

설치 전 ShareInbox 별도 백업 실패를 자료 삭제나 보존 성공으로 해석하지 않는다. 설치 후 App Group 접근과 ShareInbox 백업은 성공했지만 이전 내용과의 비교는 불가능하다. Documents의 자료·필기 보존 검증은 공유 컨테이너와 별개다.

자료·필기 비교 결과는 [device-data-preservation.json](ipad-browser-media-2026-10-21/device-data-preservation.json)에 기록했다. 주 저장소 PDF 필기 12,292행, 화이트보드 43행과 필기 저장 영수증의 모든 기존 열·값이 유지됐다. 격리된 테스트 저장소의 PDF 필기 30행도 동일했다. 전체 파일 139개 중 누락은 없으며, DB·운영 메타데이터 등 7개 파일의 내용은 실행에 따라 변경됐다. SQLite 검사는 백업 원본이 아닌 임시 사본과 WAL에서 수행했다.

[설정 비교](ipad-browser-media-2026-10-21/device-preferences-preservation.json)에서 PDF 읽기 위치 한 개가 앱 실행 중 약 0.917→0.716으로 변경됐다. 해당 문서의 다른 설정은 같고 설정 연결 이력의 기존 12개 항목은 유지된 채 하나가 추가됐다. 모든 설정값이 바이트 단위로 같다고 주장하지 않는다.

실기기는 설치·일반 실행·자료 보존을 검증했다. 성능 수치와 이번 UI 흐름 검사는 시뮬레이터 결과이며, 실제 iPad의 속도나 물리 Apple Pencil 지연을 측정한 결과가 아니다.
