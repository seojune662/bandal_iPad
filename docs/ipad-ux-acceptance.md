# iPad 사용성 전환 · 통합 검증

2026-10-15. 이번 변경은 iPad 화면·입력 정책·서비스 연결·화면 수명 관리를 담당한다. 병행 작업의 필기 기하·필압·Metal·저장 형식 변경을 보존했다. 이번 작업에서 원본 데스크톱 스냅샷을 직접 수정하지 않고 `DesktopRuntime/renderer/ipad/`의 빌드 어댑터와 네이티브 연결부를 사용했다.

## 적용한 동작

- 48px 탐색·탭 행, 중복 문서 제목/AI 행 제거, 상태바 숨김, 문서 중심 초기 화면. 탐색·자료·AI 중 한쪽만 열며 창 폭에 맞춰 전체 화면/시트/고정을 선택한다. 문서당 560px을 확보할 수 없는 분할은 편집기를 재생성하지 않고 접었다 복원한다.
- 독립된 설정 화면. 760px 미만에서는 목록과 상세를 오가며, 검색 단축키와 시작 체크리스트의 설정 이동도 해당 화면을 연다.
- PDF는 패널별 펜 상태로 시작한다. 이동식 팔레트, 펜·형광펜·지우개·선택·undo/redo, 추가 도구, 즐겨찾는 펜 3칸, 색·굵기·불투명도와 위치를 제공한다. 최근 펜과 즐겨찾기를 분리하고 명시적으로 저장한 즐겨찾기는 스타일 변경으로 밀려나지 않는다. 팔레트를 접어도 도구·스타일을 유지한다. iPad 로컬 선호 v2는 이전 위치·프리셋을 이전하며 문서 저장 형식을 바꾸지 않는다. 네이티브 첫 표시 전에 초기 도구 상태의 ACK를 확인한다.
- Markdown 본문의 Pencil 포인터·stylus touch·합성 클릭·선택·Scribble을 차단한다. 손가락·키보드·조합 이벤트를 유지하고 비활성 문서의 지연 autofocus를 막는다. PDF 전환 시 이전 Markdown 포커스를 정리한다.
- 자료 내부 드래그는 기존 이동/삽입 payload를 사용한다. 이동·공유·파일 저장은 보이는 더 보기 메뉴로 제공한다. 화이트보드와 과제 카드도 원래 메뉴를 터치 버튼으로 열 수 있다. 주요 조작은 44px 이상이며 좁고 낮은 화이트보드 도구막대는 가로로 넘긴다.
- 설정·대화상자·검색·팔레트 위로 네이티브 PDF/브라우저가 올라오지 않도록 공통 소유자·제외 영역·세대/순서 확인을 적용한다. 일시 가림은 PDF를 해제하지 않는다. 실제 화면 종료와 재시작은 이전 표면 소유권을 폐기한다.
- PDF의 동일한 배치 요청은 완료/진행 중인 ACK를 공유하고, 실제 위치·크기·가림·입력 제외 영역 변경만 전송한다. 100회 무관한 DOM 텍스트 변경에서 추가 배치 요청이 없음을 실제 훅으로 확인했다. 최신 실패는 재시도할 수 있고 오래된 실패는 새 배치를 무효화하지 않는다. 네이티브 가림 마스크도 실제 영역과 bounds가 같을 때 재사용한다.
- 작업 오류는 닫거나 명시적으로 재시도할 수 있고, 문서 오류는 해당 패널에서 복구한다. 저장 ACK가 불명확한 쓰기를 자동 재실행하거나 저장 완료로 표시하지 않는다. 정상 reload·renderer 종료·취소 후 늦은 응답이 새 화면을 되살리지 않도록 처리한다.
- 활성 탭만 바뀌어도 기존 직렬 저장 큐로 배치를 저장한다. iPad의 백그라운드·reload 저장 장벽은 문서·필기뿐 아니라 최신 배치 ACK까지 확인한다. 임시로 접은 분할 상태는 기존 배치를 덮어쓰지 않는다.
- 저장 장벽은 독립된 PDF·renderer·배치 저장 단계 중 하나가 실패해도 나머지 기존 저장 경로를 한 번씩 시도한다. 최초 오류와 대기 항목을 보존하며 전체 성공 전에는 완료를 알리지 않는다.
- 자료 감시는 과목별 공유 구독과 취소 세대를 사용한다. 변경 없는 폴링은 최대 30초까지 간격을 늘리고 실제 변경·복귀 시 다시 갱신한다. 외부 파일 변경의 유휴 반영 지연도 최대 30초임을 기록한다.
- 네이티브 alert/confirm/prompt, 공유·파일 선택 창은 완료/취소/화면 종료에서 한 번만 응답한다. CLI·실행 플러그인처럼 iPad에서 실행할 수 없는 기능은 사용 불가를 표시하고, AI 등은 설정 준비와 실제 서비스 응답 성공을 구분한다.

상세 구현과 서비스별 한계는 [화면 설계](ipad-ux-layout.md), [연결·안정성 감사](ipad-stability-audit.md)를 참조한다.
