Lifecycle constraints: pending picker/share continuations and temporary preview copies are cancelled on shell retirement; late callbacks cannot complete newer requests. Material snapshots from an older presentation generation are discarded. Failed note-close preservation retains its original writer closure for an explicit recovery retry, rather than overwriting through a second writer. Unsent native ink continues to use the existing journal and acknowledgement protocol; this slice does not change its format or persistence implementation.

The app installs one `DesktopShell` as each `WindowGroup` root (`App/BandalApp.swift`). Normal HTML reload and WebKit-process recovery keep its `DesktopShellController` and `NativePDFHost`; they do not call SwiftUI's `dismantleUIViewController`. Failed native close/checkpoint owners remain hidden in that host. Explicit document-close failure preserves its generation so the original writer can retry flush/ACK/close. Recovery attempts every retained document before returning the first failure; an unrelated document still gets its save attempt. This runs only when its existing caller requests a flush, with no new automatic retry writer.

Actual SwiftUI/window teardown reaches `dismantleUIViewController` → `detachShell` → best-effort `closeAll`. Successfully journaled strokes retain the existing on-disk replay protection. If a measured checkpoint has never reached the journal because storage remains unwritable, its failed owner is retained only inside the current native host. Deallocation of that host, or process termination, can discard those in-memory points. There is no cross-controller recovery owner or separate durable fallback for that condition. The normal-reload and explicit-retry tests do **not** establish survival across that boundary.
