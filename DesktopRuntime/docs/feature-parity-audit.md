# 원본 데스크톱 UI·기능 연결 감사

이 문서는 현재 구현의 경계를 기록한다. 원본 화면을 불러왔다는 사실을 전체 기능 완성으로 취급하지 않는다. 병행 작업으로 아래 연결 상태가 바뀌면 `backend/channel-inventory.mjs`와 해당 기능 시험을 다시 실행한다.

## 원본 보존 및 빌드

- `upstream/manifest.json`의 1,013개 파일을 SHA-256·바이트 수로 확인한다. 현재 기준은 데스크톱 **0.84.1 / be7a318**과 manifest에 명시한 작업본 변경이다. 이전 0.83.1/7d03ea5와의 개별 파일 해시 비교는 `provenance/`에 보존한다. 원본 `main.tsx`, AppShell, SettingsApp, 20개 설정 경로, Dockview, CSS, 로고·Pretendard를 그대로 사용한다.
- `renderer/bootstrap.ts`가 WK 네이티브 IPC를 먼저 설치하고 실제 원본 엔트리를 동적 로드한다. 외부 웹 페이지에는 이 IPC를 제공하지 않는다.
- `scripts/build.mjs`가 검증된 PDF 폰트 → 전체 원본 renderer → 권한 있는 backend → 원본 미리보기 parser worker → 패키지 무결성 검사를 순서대로 수행한다. `Scripts/build.sh`도 이 경로를 사용한다. Vite가 출력 폴더를 교체하므로 backend를 renderer 다음에 복사해야 한다.
- `scripts/test-package.mjs`는 내장 backend와 빌드 backend의 해시 일치, renderer가 backend를 로드하지 않는 점, 실제 주 화면·PiP·영역 선택 entry·폰트·기사 추출·격리 브라우저 도구·미리보기 자산을 확인한다.
- 원본 파일 수정 대신 검사되는 빌드 변환을 사용한다: Pencil/손가락 입력, iPad Command 키, WK 입력 파일 경로, 실제 API 키 연결, 네이티브 녹음, 계정 동기화 카드, 실행 불가능한 플랫폼 항목 설명. 원본 전체 화면을 새 UI로 재작성하지 않는다.
- 0.84.1의 Markdown/수식/표·AI 응답 화면과 원본 기본 권한 정책 변경을 renderer와 backend에 함께 반영했다. iPad 네이티브 브라우저·MCP·다른 서비스 요청의 명시적 승인은 유지한다. `typecheck`는 원본과 플랫폼 변환 후 코드를 각각 검사한다.

## 성공 응답과 미구현 구분

`backend/channel-coverage.json`은 원본 IPC 계약 전체를 분류한다. backend 테스트에서 실제 등록한 채널과 Swift의 구체적인 `case`만 증거로 사용하며 `canHandle` 접두사로 구현 수를 늘리지 않는다. `connected`는 연결 코드가 있다는 뜻이며 전체 UX·실기기 성공을 뜻하지 않는다. `partial`, `unavailable`, `unregistered`에 이유를 기록한다.

- 미등록 작업은 `UNSUPPORTED_CHANNEL` 오류를 반환한다.
- CLI 설치/로그인, Chromium 확장은 비지원 응답 또는 명시적인 오류다. 빈 확장·스킬 목록은 해당 런타임의 성공 구현으로 세지 않는다.
- MCP는 원본 암호화 registry를 네이티브 Keychain/AES-GCM에 연결하고 HTTPS Streamable HTTP의 initialize/list/call, 세션·스키마 검증, 취소, 원본 매 실행 승인을 거친다. 도구는 원본 `desktop` 대화에서만 노출되며 일반 학습에는 추가하지 않는다. 로컬 stdio 프리셋은 토큰 입력·연결 버튼부터 비활성화하고 설명한다. 실제 원격 서버로 과금/쓰기 요청을 보내지는 않았다.
- `desktop` 대화의 진입점은 별도 새 화면이 아닌 원본 자료 AI 사이드바와 같은 대화의 확대 탭이다. 원본 AI 버튼·controller·스타일을 사용한다. 별도 AI 탭은 `app`, 자동 학습은 `study`를 유지하며, 기존 대화의 저장된 종류가 UI 위치보다 우선한다.
- MCP 헤더는 CR/LF를 포함한 제어문자를 scalar 단위로 차단한다. 리디렉션은 인증 헤더 전달 없이 거부하고 서버 오류 본문/인증값을 renderer로 반환하지 않는다.
- `experimental.extensionRuntime=true` 또는 Chromium 확장 설정은 거부한다. 다른 원본 설정 저장 기능은 유지한다.
- 학습 결과는 원본 자료 해시·근거 문장 검증과 AI 종료 후에만 게시한다. 취소 후 늦은 도구·결과를 거부한다.
- 원본 노트와 잉크 저장 큐를 함께 기다리고 Markdown 스냅샷·잉크 변경 번호가 안정된 경우에만 WebKit 해제를 허용한다. 충돌·저장 실패·계속되는 편집은 성공으로 보고하지 않는다.
- 파일 input/drop은 원본 이벤트·`pathForFile` 계약을 유지하면서 256KiB 단위로 임시 파일에 전송한다. 네이티브가 연속 offset·최종 길이를 검증하고, 새 선택·전송 실패·renderer 종료 시 미완료 파일을 취소한다. 가져오기 소비 중에는 임시 파일을 고정하며, 성공이 확인된 소유 파일만 정리한다. 내보내기 복사본은 파일 선택기의 완료/취소 또는 QuickLook 닫기 이후 정리하고 과목 원본은 삭제하지 않는다.
- 초기 네이티브 앱의 `workspace:ipad`와 `reading-position`은 별도 후속 이식으로 원본 `tabs_layout`·`pdf_view_state`·마지막 과목에 연결한다. 현재 원본 UI에 이미 저장된 값은 덮어쓰지 않는다. 삭제/비공개 탭·누락된 자료·다른 문서 revision·지원되지 않는 캘린더/미이식 대화는 원본 archive를 유지하고 이유를 별도 이식 기록에 남긴다. 녹음·학습 탭은 저장돼 있던 과목의 개요로 복원하며, 저장되지 않았던 녹음/프로젝트 선택 ID를 만들지 않는다. PDFKit UserDefaults의 세부 좌표/줌은 이번 이식에 포함하지 않고 검증된 페이지를 복원한다.

## 현재 검증 근거

원본 1,013개 해시/20개 설정 경로 검사, 실제 renderer 자산 검사, Swift API 스트림·키 변경 취소·3개 제공자 이미지 입력 fixture, 실제 SQLite·파일을 쓰는 원본 backend/AI/학습 fixture, 네이티브 알림 fixture, 브라우저 승인·권한 철회·오래된 참조·비밀번호 거부·handoff fixture가 있다. 외부 제공자에 실제 과금 요청을 보내지 않았다.

- 시뮬레이터 XCUITest에서 원본 20개 설정 화면을 실제로 열고 표시·초기 오류 유무를 확인했다. 모든 설정 행의 실제 계정/장치 동작을 검증했다는 뜻은 아니다.
- Keychain 저장/오류/CSV/프로필 격리 5개 native 회귀, 실제 WK 브라우저 snapshot·identity·승인·파일 첨부·semantic key·Canvas 읽기 회귀, 원본 learning/workflow/MCP backend fixture를 통과했다. WebKit의 semantic key 동작을 신뢰된 OS 키 입력으로 보고하지 않는다.
- 공개 기사 추출은 실제 원본 Readability와 익명 네트워크 경계, hover 미리보기는 원본 parser의 격리 worker·캐시·대기열·시간 제한을 시험한다. 실서비스 사이트 호환성은 별도 조건이다.
- 원본 자료 열기 함수를 사용한 PDF/Markdown/이미지/동영상/Office/녹음·지원 불가 파일 분기와 네이티브 열기 요청의 연결을 시험했다. 이전 일반 파일 고정 분기 때문에 PDF가 열리지 않던 문제를 수정했다.
- 실제 저장소 fixture에서 새 대화의 권한을 먼저 저장한 뒤 첫 메시지를 보내는 순서를 시험했다. 원본 세션 관리자의 임시 대화와 이미 생성된 동일 대화 행을 안전하게 연결해 중복 ID 오류와 권한 유실을 막는다.
- Chromium/WebKit 파일 input/drop 회귀에서 전체 `File.arrayBuffer()` 호출 없이 12MiB 이상 파일을 256KiB 조각으로 전송하는지, 선택 교체·디스크 오류·다중 파일 실패 시 replay와 정리를 확인했다. 네이티브 staging 6개 회귀는 70MiB 복사·offset/길이 오류·디스크 부족·소비 중 취소·원본 보존을 통과했다. 일반 자료에 채팅 첨부의 64MB 제한을 적용하지 않는다.
- 후속 view-state 이식은 원본 저장소 API·`validateLayout`·실제 WebKit Dockview 복원으로 탭 순서/좌우 분할/포커스/종류를 검사했다. 기존 값 보존, DB 실패 rollback, 설정 파일 쓰기 실패 후 재개, 문서 hash/페이지/삭제/경로 검사와 재실행 멱등성을 검증했다. 필기·대화·기사 본문 전체를 다시 읽지 않고 필요한 workspace/position과 참조 자료 metadata만 조회한다.

## 아직 구현/배포가 남은 범위

- 원본 플러그인 카탈로그·검증된 아카이브 설치는 연결됐다. 개발 폴더 감시·승인·활성화·실행·로그·에디터 응답의 9개 채널은 `channel-coverage.json`의 `unregistered` 목록에 남아 있다. 설치 메타데이터/설정 저장을 플러그인 코드 실행 성공으로 세지 않는다. 원본 UI의 해당 버튼에서 호출할 때 성공으로 응답하지 않는다.
- Electron 자체 업데이트 다운로드/설치는 iPad에서 연결되지 않았다. App Store/TestFlight 배포 채널의 업데이트 정책이 필요하다.
- 사용자가 아직 준비되지 않았다고 확인한 **Google iOS OAuth 설정**과 **인증된 PPT 변환 서버**는 외부 배포 조건이다. Gmail 실제 로그인·메일 작업과 `.ppt` 실제 서버 변환의 완료를 주장하지 않는다. `.pptx` 자체 렌더링/변환 파이프라인과 구분한다.
- 로컬 CLI/stdio, OS 전역 단축키, 다른 앱 화면 조작, Chromium 확장/DevTools, 임의 교차 출처 iframe 자동화는 공개 iPad API의 제한이다. 원본 행에서 이를 명확히 설명하거나 실제 오류를 반환한다.

물리 iPad의 Pencil 압력·팜 리젝션·장시간 필기/녹음·오프라인 복귀·iPadOS 메모리 종료, 실제 로그인·학교·메일·동기화, 전체 20개 설정 사용 시나리오가 확인되기 전에는 “데스크톱과 모든 기능이 동일하게 완성됐다”고 보고할 수 없다.
